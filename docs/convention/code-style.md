# 코드 스타일 컨벤션

## 문서 목적

이 문서는 빼곡 프론트엔드에서 코드의 네이밍, 배치 순서, 상수 관리, 스타일 클래스 작성 방식을 어떻게 통일할지 정의한다.

좋은 코드 스타일 규칙은 미적인 통일감보다 탐색성과 유지보수성을 높이는 데 목적이 있다. 이 문서는 팀이 코드를 더 빠르게 읽고, 수정 영향 범위를 더 쉽게 판단할 수 있도록 기준을 제공한다.

## 네이밍 규칙

### 메시지 상수는 `MSG_{DOMAIN}_{CONTEXT}` 형식을 사용한다

텍스트 메시지 상수는 어떤 도메인에서 어떤 맥락으로 쓰이는지 이름만으로 파악할 수 있어야 한다.

- `DOMAIN`: 기능 또는 도메인
- `CONTEXT`: 사용 맥락 또는 목적

허용 예시:

```tsx
const MSG_SIGNUP_HEADER_TITLE = '회원가입';
const MSG_LOGIN_HELP = '가입/로그인 오류 문의하기';
```

## 파일 내부 코드 순서

### 파일은 읽기 흐름에 맞게 배치한다

파일 내부는 아래 순서를 기본으로 사용한다.

1. import
2. type 정의
3. 컴포넌트 전용 상수
4. 컴포넌트

이 순서는 파일을 열었을 때 의존성, 타입, 설정값, 실행 단위를 위에서 아래로 자연스럽게 읽기 위한 기준이다.

## 컴포넌트 내부 코드 순서

### 컴포넌트 내부도 일정한 순서를 유지한다

컴포넌트 내부 코드는 아래 순서를 기본으로 사용한다.

1. State, Ref
2. Data fetching, Side Effect hook
3. Memoization
4. 이벤트 핸들러, 내부 헬퍼 함수
5. Render 반환부

모든 컴포넌트가 같은 읽기 흐름을 가지면 화면 복잡도가 커져도 빠르게 구조를 파악할 수 있다.

## 상수 관리 원칙

### 상수는 의미 단위로 분리한다

상수는 단순히 값의 종류가 아니라, 어떤 맥락에서 쓰이는지를 기준으로 관리한다. 재사용 범위와 의미가 분명한 경우에는 파일로 분리하고, 특정 컴포넌트에서만 쓰이는 값은 해당 파일 안에 가까이 둔다.

### 전역 상수 파일을 만능 저장소로 사용하지 않는다

`index.ts` 하나에 서로 관계없는 상수를 계속 추가하면 파일 책임이 흐려지고 탐색성이 떨어진다. 전역 상수는 도메인이나 역할이 드러나는 파일명으로 분리하는 편이 낫다.

### export 방식은 일관되게 유지한다

상수 export는 가능한 한 named export를 우선 사용한다. named export는 사용처 추적과 리팩토링이 쉽고, 파일의 공개 대상도 더 명확하게 드러난다.

## TypeScript 규칙

### 타입 단언은 마지막 수단으로만 사용한다

`as`를 통한 타입 단언은 타입 추론, 타입 가드, 안전한 데이터 구조 설계로 해결할 수 없는 경우에만 사용한다. 타입 단언은 컴파일러 검사를 우회하기 쉬워서, 습관적으로 사용하면 런타임 오류를 숨길 수 있다.

가능하면 아래 순서를 우선 검토한다.

1. 타입 정의를 더 정확하게 만든다
2. 분기문이나 사용자 정의 타입 가드로 타입을 좁힌다
3. 함수 반환 타입이나 API 응답 타입을 명확하게 선언한다

### non-null assertion은 사용하지 않는다

`value!`처럼 null 가능성을 강제로 제거하는 표현은 사용하지 않는다. 이 방식은 실제 null 케이스를 가린 채 런타임 오류를 만들기 쉽다.

값이 반드시 존재해야 한다면, 먼저 조건문으로 검사하거나 early return으로 흐름을 분리한다.

### `as const`는 리터럴 타입 고정 목적에 한해 허용한다

`as const`는 상수 객체나 상수 배열의 리터럴 타입을 고정해야 하는 경우에만 사용한다. 단순히 타입 에러를 피하기 위한 용도로 사용하지 않는다.

## 스타일 클래스 규칙

### 조건부 스타일 클래스는 JSX 밖에서 분리한다

조건에 따라 달라지는 스타일 클래스는 JSX 내부에서 직접 조합하지 않고, 상수나 변수로 분리해서 선언한다. 이 기준은 마크업과 스타일 결정 로직을 섞지 않기 위한 것이다.

허용 예시:

```tsx
const sizeClass = size === 'small' ? 'h-8 px-3 text-sm' : 'h-12 px-5 text-base';

return <button className={`${sizeClass} inline-flex items-center justify-center`}>Click</button>;
```

### 스타일 관련 변수명은 의미 기반으로 작성한다

`className1`, `tempClass`처럼 임시 이름을 쓰기보다, 해당 값이 어떤 역할을 하는지 드러나는 이름을 사용한다.

## Spacing 규칙

### spacing 값은 `rem` 기반으로 작성한다

선 굵기처럼 예외적인 경우를 제외하면 spacing은 `rem` 기반으로 작성한다. 고정 픽셀 단위를 직접 남용하면 스케일 일관성이 무너질 수 있다.

### Tailwind spacing scale을 우선 사용한다

Tailwind 기본 spacing scale로 표현 가능한 값은 우선 그 값을 사용한다. scale로 표현할 수 없는 경우에만 `rem` arbitrary value를 사용한다.

### 픽셀 단위 spacing은 직접 사용하지 않는다

`top-[10px]`, `px-[2px]` 같은 spacing 표현은 사용하지 않는다.
