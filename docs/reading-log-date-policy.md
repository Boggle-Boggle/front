# 독서기록 날짜 정책 초안

## 목적

독서기록 생성 및 수정 화면에서 독서 상태별 날짜 선택 가능 범위와 저장 검증 기준을 정리한다.

이 문서는 구현 전 정책 합의를 위한 초안이다. 확정 후 `src/policy` 아래 정책 코드와 캘린더 validation에 반영한다.

## 용어

- 시작일: 독서를 시작한 날짜
- 종료일: 독서를 끝냈거나 중단한 날짜
- 오늘: 사용자가 화면을 열거나 저장을 시도하는 시점의 현재 날짜
- 미래 날짜: 오늘보다 이후인 날짜

## 독서 상태

현재 독서기록 날짜 정책은 아래 상태를 기준으로 나눈다.

- 다 읽은 책
- 읽는 중인 책
- 중단한 책

## 상태별 날짜 정책

| 독서 상태 | 시작일 정책 | 종료일 정책 |
| --- | --- | --- |
| 다 읽은 책 | 미래 날짜 선택 불가 | 미래 날짜 선택 불가, 시작일과 같거나 이후 날짜만 선택 가능 |
| 읽는 중인 책 | 미래 날짜 선택 불가 | 종료일을 사용하지 않음 |
| 중단한 책 | 미래 날짜 선택 불가 | 미래 날짜 선택 불가, 시작일과 같거나 이후 날짜만 선택 가능 |

## 필수값 정책

### 시작일

시작일은 모든 독서 상태에서 필수값으로 본다.

- 다 읽은 책: 시작일 필수
- 읽는 중인 책: 시작일 필수
- 중단한 책: 시작일 필수

### 종료일

종료일은 독서 상태에 따라 필수 여부가 달라진다.

- 다 읽은 책: 종료일 필수
- 읽는 중인 책: 종료일 사용 안 함
- 중단한 책: 종료일 필수

## 날짜 순서 정책

종료일이 존재하는 상태에서는 종료일이 시작일보다 이전일 수 없다.

- 허용: 시작일과 종료일이 같은 날
- 허용: 종료일이 시작일 이후인 날
- 불가: 종료일이 시작일 이전인 날

즉, 종료일 조건은 `startDate <= endDate`로 본다.

## 상태 변경 시 보정 정책

독서 상태 또는 날짜 변경으로 기존 날짜 값이 정책을 벗어나는 경우 아래 기준으로 보정한다.

### 읽는 중인 책으로 변경

읽는 중인 책은 종료일을 사용하지 않는다.

- 화면에서는 종료일을 표시하지 않는다.
- 저장 시 종료일을 전송하지 않는다.

### 종료일이 필요한 상태로 변경

다 읽은 책 또는 중단한 책으로 변경했는데 종료일이 없으면 종료일을 오늘로 초기화한다.

단, 시작일이 오늘보다 이전이고 오늘이 허용 가능한 범위에 포함되는 경우에 한한다.

### 시작일이 종료일보다 뒤로 변경

종료일이 필요한 상태에서 시작일이 종료일보다 뒤가 되면 종료일을 시작일로 보정한다.

### 시작일이 미래 날짜가 된 경우

시작일이 미래 날짜가 되면 시작일을 오늘로 보정한다.

### 종료일이 미래 날짜가 된 경우

종료일이 미래 날짜가 되면 종료일을 오늘로 보정한다.

## 캘린더 선택 가능 범위

캘린더 컴포넌트에는 독서 상태와 선택 필드에 따라 아래 범위를 전달한다.

| 독서 상태 | 선택 필드 | minDate | maxDate |
| --- | --- | --- | --- |
| 다 읽은 책 | 시작일 | 없음 | 오늘 |
| 다 읽은 책 | 종료일 | 시작일 | 오늘 |
| 읽는 중인 책 | 시작일 | 없음 | 오늘 |
| 읽는 중인 책 | 종료일 | 사용 안 함 | 사용 안 함 |
| 중단한 책 | 시작일 | 없음 | 오늘 |
| 중단한 책 | 종료일 | 시작일 | 오늘 |

## 저장 전 최종 검증

UI에서 선택을 막더라도 저장 직전에는 동일한 정책으로 최종 검증한다.

저장 불가 조건은 아래와 같다.

- 시작일이 없는 경우
- 시작일이 미래 날짜인 경우
- 종료일이 필요한 상태에서 종료일이 없는 경우
- 종료일이 필요한 상태에서 종료일이 미래 날짜인 경우
- 종료일이 필요한 상태에서 종료일이 시작일보다 이전인 경우

읽는 중인 책은 저장 시 종료일을 전송하지 않는다.

## 신규 독서기록 기본값

신규 독서기록 생성 시 기본 날짜는 아래 기준을 따른다.

| 독서 상태 | 시작일 기본값 | 종료일 기본값 |
| --- | --- | --- |
| 다 읽은 책 | 오늘 | 오늘 |
| 읽는 중인 책 | 오늘 | 없음 |
| 중단한 책 | 오늘 | 오늘 |

## 구현 방향 메모

정책 코드는 `src/policy/date.ts`에서 관리한다.

캘린더 컴포넌트는 독서기록 정책을 직접 알지 않는다. 캘린더는 `minDate`, `maxDate`를 받아 선택 가능 여부를 표현하고 선택을 막는 역할만 담당한다.

날짜 포맷팅, 파싱, 오늘 날짜 문자열 생성 등 순수 유틸은 기존 `src/utils/date.ts`를 사용한다.

## 확인 필요 항목

- 중단한 책의 종료일을 항상 필수로 둘지 확인한다.
- 시작일과 종료일이 같은 날인 기록을 허용할지 확인한다.
- 읽는 중인 책으로 상태를 바꿀 때 기존 종료일 값을 완전히 비울지, 화면에서만 숨길지 확인한다.
- 상세 수정 화면에도 신규 생성 화면과 동일한 날짜 정책을 강제할지 확인한다.
